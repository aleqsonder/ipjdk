# Протокол размещения данных

Настоящий документ содержит описание формата данных,
составляющих Java-объекты, при их размещении в
неуправляемой (с точки зрения JVM) памяти.


# Типы данных

Данный протокол разрабатывается с целью последующего
его использования для хранения разделяемых данных,
из чего следует необходимость запрета размещения содержимого
экземпляров встроенных классов Java, поскольку
встроенные классы Java могут храненить указатели на области
виртуальной памяти одного из процессов, что может привести
к неопределенному поведению программы при осуществлении
межпроцессной коммуникации.

В неуправляемой памяти допустимо размещать значения
примитивных типов данных Java, а именно:

- byte;
- short;
- int;
- long;
- float;
- double;
- boolean;
- char.

Также в неуправляемой памяти можно размещать указатели
на другие области этой памяти, представленные смещениями
от начала данного участка памяти. Это позволяет хранить
в неуправляемой памяти массивы и сложные структуры данных.
Тип данных, используемый для хранения таких смещений,
обозначим как `pointer`.


# Идентификация способа размещения содержимого объектов

Чтобы виртуальная машина могла однозначно отличить
обычный Java-объект от объекта, значения полей которого
хранятся в неуправляемой памяти, для выбора поведения
инструкции, взаимодействующей с полем объекта, в библиотеку
вводится абстрактный класс `Shared`. Экземпляры всех классов,
прямо или косвенно наследующих `Shared`, автоматически
идентифицируются виртуальной машиной Java, как объекты,
содержимое полей которых размещено в неуправляемой памяти.


# Разметка

## Управляемая память

Разметка области управляемой памяти, соответствующей
экземпляру того или иного наследника класса `Shared`
полностью определяется реализацией JVM (что
справедливо для всех классов в Java). Класс `Shared`
разработан в том числе для хранения дополнительного
поля `ptr`, значение которого соответствует значению
нативного указателя на область неуправляемой памяти,
отображенной в виртуальную память процесса.
Прочие поля объекта добавляются в рамках классов,
наследующих `Shared`.

В рамках модификации **IPJ** не планируется изменять
порядок разметки управляемой памяти JVM для хранения
в ней Java-объектов - локальная память процесса
может быть использована в будущем для обеспечения
асинхронного чтения и записи областей разделяемой
памяти, при которых управляемая память сыграет
роль временного буфера.

## Неуправляемая память

### Поля

Для каждого поля объекта выделяется область памяти, размер
которой соответствует ее типу данных. Таблица ниже
содержит отображение примитивного типа данных на
потребляемый объем памяти, где `pointer` - тип
для хранения ссылки на область неуправляемой памяти.

| Тип данных    | Размер (байт) |
|---------------|---------------|
| byte          | 1             |
| short         | 2             |
| int           | 4             |
| long          | 8             |
| float         | 4             |
| double        | 8             |
| char          | 1             |
| pointer       | 8             |

Все поля размещаются в памяти друг за другом без
выравнивания. Таким образом для хранения
полей экземпляра класса `X`:

```java
class X extends Shared {
	byte a;
	int b;
	double c;
	char[] d;
	Shared e;
	X[] f;
}
```

в соответствующей данному объекту области неуправляемой памяти
будет порождена следующая структура данных:

| Имя | Тип     | Размер (байт) | Отступ (байт) |
|-----|---------|---------------|---------------|
| `a` | byte    | 1             | 0             |
| `b` | int     | 4             | 1             |
| `c` | double  | 8             | 5             |
| `d` | pointer | 8             | 13            |
| `e` | pointer | 8             | 21            |
| `f` | pointer | 8             | 29            |

### Дополнительная информация

В целях обеспечения типобезопасного обращения
к полям объекта, размещенного в неуправляемой памяти,
помимо значений непосредственно полей, в начало разметки
объекта добавлен 8-байтовый идентификатор типа,
вычисляемый автоматически на основе представленных
в описании класса полей, или задаваемый пользователем
вручную (посредством явного определения статической
константы с именем `IPJ_CLSID` в классе, наследующем
`Shared`).

Таким образом разметка области неуправляемой памяти,
соответствующей экземпляру класса `X` может быть
представлена таблицей ниже:

| Имя         | Тип     | Размер (байт) | Отступ (байт) |
|-------------|---------|---------------|---------------|
| `IPJ_CLSID` | long    | 8             | 0             |
| `a`         | byte    | 1             | 8             |
| `b`         | int     | 4             | 9             |
| `c`         | double  | 8             | 13            |
| `d`         | pointer | 8             | 21            |
| `e`         | pointer | 8             | 29            |
| `f`         | pointer | 8             | 37            |
